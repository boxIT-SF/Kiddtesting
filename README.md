# Disk Space Analyzer

A Windows application that scans a volume, works out **what the data actually is**, **how old it
is**, **whether it is safe to delete**, and — where it is not — **what to do instead**. It then
sizes and orders a plan that leaves the volume with a chosen number of months of headroom
(six by default).

It runs as a desktop window for interactive triage, and as a command-line script for scheduled
runs from an RMM. Nothing is ever deleted without an explicit instruction.

```
Scan  ->  Classify  ->  Age profile  ->  Growth estimate  ->  Plan  ->  Report / cleanup script
```

---

## Why not just sort by size

Sorting a volume by file size tells you `pagefile.sys` is 16 GB and `Finance_log.ldf` is 25 GB.
Neither of those can be deleted, and knowing their size does not tell you what to do. This tool
answers the questions that follow:

| Question | Where the answer comes from |
|---|---|
| What is this data? | A rule set of ~58 classifications covering Windows servicing, caches, crash data, shadow copies, mail, cloud sync, server workloads, logs and user data |
| Is it safe to delete? | Each classification carries **Safe**, **Review** or **Unsafe**, plus the reason |
| If not, what can I do? | Every Unsafe and Review classification carries a remediation — the supported way to shrink, move or cap the data |
| How much do I need to free? | Projected growth over the horizon, plus an operating reserve, minus what is free today |
| What do I clear, in what order? | Actions ordered safest first, then by how confidently the data was identified, then by size — stopping when the target is met |
| How do I stop it coming back? | Preventive controls derived from what was actually found |

**Safety levels**

- **Safe** — regenerated by the OS or the application, or already a copy of something else. An automated job can remove it.
- **Review** — almost certainly reclaimable, but the owner, the size or a retention requirement has to be confirmed first.
- **Unsafe** — never delete directly. The remediation says what to do instead.

## Requirements

- Windows 10 / 11, or Windows Server 2016 or later
- Windows PowerShell 5.1 (in the box) or PowerShell 7
- No installation, no dependencies, no internet access needed
- Runs unelevated; elevation adds the hibernation, page file, shadow copy and stale profile probes,
  and is needed to read some system folders

## Quick start

**Desktop window**

```
tools\Start-DiskSpaceAnalyzer.cmd
```

Or from a PowerShell prompt:

```powershell
Import-Module .\src\DiskSpaceAnalyzer\DiskSpaceAnalyzer.psd1
Show-DiskSpaceAnalyzer -Path C:\ -HorizonMonths 6
```

Pick a volume, press **Scan**, and work through the tabs: *Summary* for the recommendation,
*Plan* for what to clear, *Do not delete* for the large data that needs a different approach,
*Oldest data* for what has been sitting there longest. The buttons at the bottom save an HTML
report, a JSON document, or a cleanup script.

**Command line**

```powershell
# Look at C: and print the analysis
.\tools\Invoke-DiskSpaceAnalyzer.ps1 -Path C:\ -Months 6

# Scheduled run: write a report to a share, say nothing on the console
.\tools\Invoke-DiskSpaceAnalyzer.ps1 -Path C:\ -Quiet `
    -Report \\fs01\reports\$env:COMPUTERNAME.html `
    -CleanupScript \\fs01\reports\$env:COMPUTERNAME-cleanup.ps1
```

Exit codes, so a monitoring system can act on the result:

| Code | Meaning |
|---|---|
| 0 | The volume has, or can reach, the requested months of headroom |
| 1 | Cleanup alone cannot get there — the volume needs data moved off it or more capacity |
| 2 | The analysis failed |

## What a report contains

1. **Recommendation** — a handful of plain sentences: how full the volume is, how long it has left
   at the current rate, how much has to be freed, and whether cleanup alone can do it.
2. **Step 1 — reclaim** — the actions, safest first, each with what the data is, why it is safe or
   what decision is needed, and the command to run.
3. **Step 2 — large data that must not simply be deleted** — where the space really went, and the
   supported remediation for each: shrink the transaction log after a log backup, merge the stale
   Hyper-V checkpoint, cap shadow copy storage, turn on Files On-Demand, move the PST to a backed-up
   share.
4. **Step 3 — keep it clear** — the retention policies, Storage Sense settings, log rotation and
   monitoring thresholds that stop the space coming back inside the horizon.
5. **Oldest data**, **age profile**, **classification breakdown**, **where the space went**,
   **largest files**.
6. **How these numbers were produced** — every assumption behind the plan, the confidence in the
   growth estimate, and any folder the scan could not read.

The HTML report is a single self-contained file with no external references, so it can be emailed
or attached to a ticket and still render.

## How the six-month number is worked out

```
target free space  =  (growth per month  x  months  x  safety factor)  +  operating reserve
shortfall          =  target free space  -  free space today
```

- **Growth per month** is the median of the last twelve complete months of file creation. The
  median rather than the mean, so one month containing a migration does not dominate the forecast.
- **Safety factor** defaults to 1.25, so a slightly low estimate does not sink the plan.
- **Operating reserve** is the level the volume should not drop below at the end of the horizon —
  the greater of 15 % of capacity and 10 GB, capped at 25 % of capacity so the floor cannot
  swallow a small volume.

Then actions are taken in order — everything **Safe**, then the identified **Review** items, then
anything unidentified — until the shortfall is covered. **Unsafe** data never counts toward the
target.

**What the growth estimate cannot see**, stated in every report:

- files that were created and later deleted, so churn is understated;
- existing files that grow in place — databases, virtual disks, append-only logs;
- creation timestamps rewritten by a bulk copy, which inflates the most recent months.

Where a real trend line already exists, use it instead:

```powershell
Invoke-DiskSpaceAnalysis -Path C:\ -KnownGrowthBytesPerMonth 4GB
.\tools\Invoke-DiskSpaceAnalyzer.ps1 -Path C:\ -GrowthGBPerMonth 4
```

`docs/METHOD.md` goes through this in more detail, including the accuracy traps the scanner
handles (cloud placeholders, sparse files, hard links, reparse points).

## Cleaning up

The tool separates *deciding* from *doing*. Generate a script, read it, then run it:

```powershell
$result = Invoke-DiskSpaceAnalysis -Path C:\
$result | New-DsaRemediationScript -Path .\cleanup-SRV01.ps1

.\cleanup-SRV01.ps1            # dry run - reports what it would remove, changes nothing
.\cleanup-SRV01.ps1 -Execute   # applies the Safe steps
```

The generated script only ever automates classifications marked **Safe**. Everything else is
written into it as a commented block with its remediation, so the script doubles as the change
record. Free space is reported before and after.

For a single class of data:

```powershell
Remove-DsaClassifiedFile -RuleId win-update-cache -Path C:\ -WhatIf
Remove-DsaClassifiedFile -RuleId win-update-cache -Path C:\ -Confirm:$false
```

This refuses Unsafe classifications outright, requires `-AllowReviewClass` for Review ones, will
not let you lower a rule's age threshold, and never touches a cloud placeholder.

## Teaching it about your environment

Classifications live in `src/DiskSpaceAnalyzer/Data/ClassificationRules.psd1`. Rather than editing
that file, drop an overlay next to it — rules are merged by `Id`, so an overlay can replace a
shipped rule or add a new one:

```powershell
# SiteRules.psd1
@{
    Rules = @(
        @{
            Id          = 'lob-scanned-invoices'
            Name        = 'Scanned invoice archive'
            Category    = 'Business data'
            Safety      = 'Unsafe'
            Priority    = 5
            PathPattern = '\\InvoiceArchive\\'
            Description = 'Scanned invoices retained for the statutory period.'
            Reason      = 'Retention is a statutory requirement, not a preference.'
            Remediation = 'Move anything past the retention date to the archive tier; never delete in place.'
        }
    )
}
```

```powershell
Invoke-DiskSpaceAnalysis -Path D:\ -RuleFile .\SiteRules.psd1
```

Lower `Priority` wins. `PathPattern` and `NamePattern` are case-insensitive regular expressions
matched against the directory and the file name; `Extensions` is a list including the dot;
`EligibleAfterDays` keeps young files out of the plan while still classifying them.

To see what is loaded:

```powershell
Get-DsaClassificationRule | Format-Table Priority, Id, Safety, Name -AutoSize
```

## Command reference

| Command | Purpose |
|---|---|
| `Show-DiskSpaceAnalyzer` | Open the desktop window |
| `Invoke-DiskSpaceAnalysis` | Run the whole analysis and return the result object |
| `Export-DsaReport` | Write the result as HTML, text, JSON or CSV |
| `New-DsaRemediationScript` | Generate the guarded cleanup script |
| `Remove-DsaClassifiedFile` | Delete one classification's files, with its safety level enforced |
| `Get-DsaFileInventory` | Stream file records from a tree (the scanner on its own) |
| `Measure-DsaInventory` | Aggregate file records into the analysis |
| `Get-DsaVolumeInfo` | Capacity and free space for a path |
| `Get-DsaSystemReclaimOpportunity` | Probe for space a file walk cannot see |
| `Measure-DsaGrowthRate` | Estimate growth from the inventory |
| `New-DsaSpacePlan` | Build the capacity plan from a summary |
| `Get-DsaClassificationRule` | Load and inspect the rule set |
| `Resolve-DsaFileCategory` | Classify one file |
| `New-DsaClassifier` | Build a reusable classification context |

Every command has full help: `Get-Help Invoke-DiskSpaceAnalysis -Full`.

## Performance

The scanner streams rather than collecting, so memory stays flat regardless of file count. On a
volume with millions of files the two settings that matter are:

```powershell
# Skip small files entirely - several times faster, and it barely moves the reclaimable totals
Invoke-DiskSpaceAnalysis -Path C:\ -MinFileSizeBytes 1MB

# Skip a tree you already know about
Invoke-DiskSpaceAnalysis -Path C:\ -ExcludePattern '\\SQLData\\', '\\VMs\\'
```

Reparse points are not followed by default, so junctions and symlinks do not cause data to be
counted twice or the walk to cycle.

## Tests

```powershell
pwsh -File .\tests\Invoke-Tests.ps1
# or, on Windows PowerShell
powershell -ExecutionPolicy Bypass -File .\tests\Invoke-Tests.ps1
```

85 tests covering the helpers, rule set invariants, classification, the scanner, aggregation,
growth estimation, the plan arithmetic, the deletion guards, and every report format. The harness
is self-contained — no Pester, no gallery access — because the machines this tool is aimed at
often have neither.

Two of those tests are the ones worth knowing about, because they protect the promise the tool
makes: *every Unsafe classification must carry a remediation*, and *the generated cleanup script
must never automate anything that is not Safe*.
